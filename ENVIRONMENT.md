ENVIRONMENT & Secrets
=====================

This repository requires several environment variables for local development and production (database, Stripe, email providers, ImageKit, etc.). Follow these rules to keep secrets safe.

Local env files

- Use a local-only file for secret values: `.env.local`. Do NOT commit this file.
- Use `.env.example` as a template to fill required variables.
- Never add real secrets to commits or open PRs.

Git safety

- Ensure `.env*` patterns are present in `.gitignore` (already configured in this repo).
- Run a local secret scan before pushing if you are unsure about recent changes.

Secret scanning (recommended)

- A GitHub Actions secret-scan workflow checks PRs and pushes for high-entropy secrets.
- Locally, use tools such as TruffleHog, Semgrep, or the lightweight scanner in `scripts/secret-scan-local.js`.

If secrets were accidentally committed

- Rotate the exposed secrets immediately with the provider (Stripe, Resend, ImageKit, etc.).
- To scrub history (only if necessary and you understand the consequences) use `git filter-repo` or BFG to remove the file(s) from history, then force-push.

Example (BFG):

    bfg --delete-files .env.local
    git reflog expire --expire=now --all
    git gc --prune=now --aggressive
    git push --force

For `git filter-repo` see [git-filter-repo](https://github.com/newren/git-filter-repo)

CI & pre-merge checks

- The repo contains a `secret-scan.yml` workflow that runs TruffleHog on PRs and pushes to `master`/`main`.
- The CI workflow also runs lint and build on PRs to catch regressions early.

Best practices

- Store production secrets in your hosting provider's secret manager (Vercel, Netlify, Azure Key Vault, AWS Secrets Manager, etc.).
- Use short-lived API keys where possible and rotate them regularly.
- Use per-service credentials and avoid reusing keys across services.

Contact / help

- If you're unsure about a reported secret, ask a teammate or open an internal incident. Rotate keys if in doubt.
